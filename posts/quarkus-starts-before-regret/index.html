Quarkus Makes Java Start Before You Regret Choosing Java

The JVM can now fail before Prometheus has discovered the pod.

Quarkus 3.32 integrated Project Leyden’s AOT cache support. Quarkus reported a minimal REST application improving from roughly 370 milliseconds to 80 milliseconds, while a larger 9,000-class application improved from about three seconds to 900 milliseconds after training.

Java startup is now so fast that your Kubernetes pod can fail before Prometheus has discovered it.

Project Leyden records class loading, linking and profiling during a training run, then packages that knowledge into a cache for later executions.

This is called ahead-of-time optimization.

It should not be confused with native compilation, class-data sharing, profile-guided optimization, CRaC checkpoints, application class-data sharing, static images or keeping the JVM running — which remains the most reliable way to make its second startup instantaneous.

The benchmark results are impressive.

A minimal REST application starts in 80 milliseconds, meaning it can now begin listening before the service mesh, policy agent, telemetry collector, secrets sidecar and twelve Kubernetes controllers have finished preventing anyone from reaching it.

Java startup was once the bottleneck.

We fixed it.

The bottleneck is now everything invented to compensate for Java startup.
