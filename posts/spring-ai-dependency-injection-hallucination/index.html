Spring AI Brings Dependency Injection to Hallucination

The hallucination has passed through nine beans and is visible in Grafana.

Spring AI 2.0 ships the MCP Java SDK 2.0, annotation-driven MCP tools and resources, composable advisor chains, tool-search facilities, structured-output correction, memory, observability and agent-oriented utilities. A Spring service can become an MCP tool with a method annotation.

At last, Java developers can make probabilistic systems deterministic by annotating them.

@McpTool
@Transactional
@Retryable
@Observed
public StrategicInsight determineCorporateFuture() {
    return model.call("Please do not make anything up.");
}

The model may invent a customer, call the wrong tool and return malformed JSON, but it will do so inside a properly ordered advisor chain with Micrometer spans.

This is enterprise readiness.

Spring AI begins innocently with one @Tool.

Then you add memory.

Then observability.

Then retries.

Then structured-output validation.

Then dynamic tool discovery because you have hundreds of tools.

Then an advisor controlling which advisor may re-enter the downstream advisor chain during the recursive tool loop.

Six months later, the chatbot still cannot answer “When do we close on Friday?”, but its hallucination has passed through nine beans and is visible in Grafana.

The Spring community has successfully transformed:

Call a function.

into:

Declare a managed capability whose invocation participates in an extensible, observable, recursively advised agentic lifecycle.

Nature is healing.
